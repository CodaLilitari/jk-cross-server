# Stock starting-heading rejection in the protected memory run

**Finding.** The two initial orientations are correct for their assigned stock-engine yaw. The validator used ideal mathematical sine and cosine, whereas the frozen game uses a quarter-wave lookup table. An independent binary32 calculation from the pinned table and the measured edge reconstructs every bit of the initial facing in both rejected attempts. The official frozen block correctly records two invalid attempts under its declared verifier; this investigation supplies no new physical result and changes no score.

## Arithmetic and source chain

The source snapshot is bfe9aa52957046375ca34733debdc8eb1ece3520. native/tests/stock_water_replay/collect_motor.py:21 sets TRACE_YAW from the job; evaluate_motor.py:224 passes that environment on the model arm. replay_loop.inc:63–64 starts facing along the horizontal wet-to-dry vector. The linked engine sources under the measured run's build/source/src supply the arithmetic: AI/jkBot.c:107–112 uses subtraction and sqrtf for the horizontal basis; Primitives/rdMatrix.c:18–35 and :118–121 use stdMath_SinCos for yaw; :498–505 and :551–556 perform the matrix multiply. General/stdMath.c:148–175 normalizes yaw and indexes a 4,096-entry quarter wave. For +45° (index 2,048, zero fractional part) lines 192–202 yield sine T[2048] and cosine T[4095−2048] = T[2047]. For −45°, the positive equivalent is 315°, index 14,336, zero fraction; lines 234–245 yield sine −T[2047] and cosine T[2048]. Binary32 values of the literals in General/stdMathTables.h are T[2047] = 0.7068359851837158 and T[2048] = 0.7071070075035095. At +90° the table gives sine T[4095] = 1 and cosine −T[0] = 0. The declaration binds both math sources and the table in qa/lily-memory-declaration.json:452–478.

Independently round the recorded node coordinates to binary32, subtract and divide by their binary32 horizontal length as in the native source. The resulting initial basis is (0.9222152829170227, 0.3866769075393677). Applying the table coefficients with a binary32 rounding on each product/addition predicts exactly (0.9254220724105835, −0.3784329891204834) at −45°, (0.3784329891204834, 0.9254220724105835) at +45°, and (−0.3866769075393677, 0.9222152829170227) at +90°. Converting the printed observations back to binary32 gives the same three 32-bit components for each predicted facing. No raw terminal, engine run, resimulation or modified source was needed.

By contrast, native/tests/stock_water_replay/evaluate_motor.py:117–125 computes a double-precision normalized edge and uses Python math.cos/sin, checking each facing and up coordinate with math.isclose(abs_tol=2e-5). It agrees at training/open cardinal headings. The declared transfer yaw bank uses only −45°, +45°, +135°, −135°, while the earlier calibration and open banks contain only cardinal yaws. That coverage gap explains why this first surfaced on transfer. The explicit signed-yaw traces and bit-level matches rule out swapped axes, reversed sign, incorrect assigned starting position and timing as explanations for these two discrepancies.

## Minimal prospective change and verification

Keep the native starting conditions, policy and binary movement fixture unchanged. For a new declaration, change the independent heading expectation to the authenticated stock rotation. All yaw values in the six current TSVs are multiples of 45°, so a small degree-to-(sin,cos) mapping with source-generated, reviewed quadrant coefficients is sufficient for this declared domain. Pin the mapping or its derivation to the exact stdMath and table hashes, and explicitly reject an unsupported yaw instead of silently treating it as cardinal or applying the nearest mapping. If a more general yaw domain is required, port the precise quadrant/interpolation and normalization paths, or derive an independent complete lookup from the bound source. Keep the existing tight bound and independent up-axis check. Broadening the tolerance to fit two samples would allow arbitrary errors of similar magnitude and leave its physics basis unexplained.

Use offline unit tests with a non-axis-aligned synthetic wet/dry edge at all eight declared headings, covering each quadrant and the ± signs, including ±135° without running another sealed start. Freeze expected values from stock math independently of the validator (an isolated math-only test invoking the pinned orientation functions is suitable). For the measured examples the binary32 bits above can be regression witnesses without publishing the underlying map coordinates. Include negative tests for exchanged signs/axes, corrupted input yaw, a small facing perturbation exceeding the retained tolerance and a corrupted up vector. Retain the different checks for actor identity, supported ownership and physics results. Confirm correct candidate/native open-start tuples and reject tampered stage receipts under the appropriate protocol.

The prior transfer comparison remains unscored. Preserve its null transfer criterion, the two invalid records and 286 unrun assignments. Any new corrective audit on the two stored traces or later release of additional assignments must use an explicitly versioned prospective protocol, account for the prior exposure of these two v3 cases, and leave the original freeze and receipts intact. No evidence here establishes transfer for either learned controller.
